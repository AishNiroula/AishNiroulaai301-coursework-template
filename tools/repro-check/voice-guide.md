## Rules I write by

### Rule: Promise the investigation, not the fix

I only promise to reproduce and report, never a fix or a date.

- Wrong: "I'll have a fix up by Friday."
- Right: "I'll try to reproduce this and post what I find."

### Rule: Name the specifics

A claim mentions something only this issue has.

- Wrong: "I'd like to work on this issue."
- Right: "I'll look at the failing call described in this issue and post my repro."

### Rule: Never piggyback

My proof is my own run, in my words.

- Wrong: "Same as above, can confirm."
- Right: "I ran this on macOS with Python 3.13 and saw: <output>."

### Rule: Disclose AI use when asked

If the repo's policy requires it, I say how I used AI.

- Wrong: (posting with no mention)
- Right: "I used Claude Code to help set up the environment; I ran and checked the commands myself."


## Things I never post

<!-- A short list. Promises you cannot keep, tones you refuse,
shortcuts you know you reach for when tired. The skill quotes this
list back at you when a draft crosses it. -->

- A promised fix or deadline.
- "Confirmed" without my own output attached.
- A guess at a root cause presented as fact.
- A comment I did not run through my skill first.
